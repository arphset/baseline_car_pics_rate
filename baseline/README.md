# Эвристическое базовое решение

Модуль `quality_baseline` оценивает техническое качество фотографии (резкость, экспозиция, заполнение кадра, положение объекта) и в режиме `car` проверяет, годится ли снимок на роль главного фото объявления о продаже автомобиля. Обучения нет: все решения принимаются по порогам и штрафам из `config.py`. С этим решением во второй части работы сравниваются дообученные классификаторы типа кадра.

Модуль построен на ядре оценки проекта [QualityJPG](https://github.com/arphset/QualityJPG---Made-in-Abyss) (`ML&CV_Module`) и адаптирован для фотографий автомобилей (см. [отличия](#отличия-от-qualityjpg)).

## Запуск

```bash
pip install -r requirements.txt
python run_baseline.py ../dataset/1117265871-06c15a34 --mode car --out results/my_run
python check_reproduction.py                      # все 140 фото раздела 2.4 + сравнение с сохранёнными результатами
python evaluate.py results/pics_with_auto_for_test/results.json labels_pics_with_auto_for_test.json
```

`--mode generic` — только технические критерии для любых изображений; `--mode car` — плюс проверки главного фото автомобиля. Флаг `--profile original` включает исходные формулы экспозиции и резкости QualityJPG и оставлен только для справки; все результаты курсовой получены с профилем по умолчанию.

В папке `--out` сохраняются:
- `report.csv` — краткий отчёт с русскими колонками (балл, вердикт, годится ли на главное, проблемы, штрафы);
- `results.csv` — все метрики;
- `results.json` — все метрики и каждая детекция YOLO.

Из Python:

```python
from quality_baseline import analyze
r = analyze("img_01.jpg", mode="car")
print(r["score"], r["issues"], r["main_photo_ok"])
```

## Структура

| Файл | Назначение |
|---|---|
| `quality_baseline/blur.py` | оценка резкости: лапласиан (по области и по блокам), градиент Собеля, автокорреляция, смаз движения |
| `quality_baseline/exposure.py` | оценка экспозиции: доли выбитых пикселей, средняя яркость |
| `quality_baseline/detection.py` | детекция YOLOv8n, заполнение кадра, центрирование, контекстные проверки автомобиля |
| `quality_baseline/scoring.py` | технический балл от 1 до 10 со штрафами |
| `quality_baseline/pipeline.py` | функция `analyze()`, объединяющая все проверки |
| `quality_baseline/config.py` | все пороги и веса |
| `run_baseline.py` | запуск из командной строки на папке изображений |
| `evaluate.py` | расчёт метрик пригодности по ручной разметке |
| `check_reproduction.py` | повторный прогон 140 фото и сравнение с сохранёнными результатами |

## Режим `car`

Проверки главного фото, которые можно выполнить детектором без обучения:
- на фото есть автомобиль: рамка класса car или truck с уверенностью от 0,4 (truck — потому что внедорожники YOLO часто относит к нему);
- автомобиль не касается края кадра и занимает не меньше 30 % кадра;
- нет других автомобилей крупнее половины основного (повторные рамки одной машины с IoU > 0,5 не учитываются);
- нет людей и посторонних объектов площадью от 1 % кадра.

Итог `main_photo_ok`: фото технически годно (балл не ниже 7,5 и нет дефектов резкости или экспозиции) и контекстных проблем нет. Технический балл и контекстные проверки хранятся раздельно.

Тип кадра (спереди, сбоку, сзади, салон, багажник и т. д.) базовое решение не определяет: для детектора и вид сбоку, и вид сзади — один и тот же класс car. Это задача классификатора во второй части работы.

## Отличия от QualityJPG

| В QualityJPG | В базовом решении | Зачем |
|---|---|---|
| ядро связано с интерфейсом и языковой моделью | отдельный пакет: OpenCV, NumPy, ultralytics | запуск одной командой на папке |
| метрики выводятся через `print` | возвращаются словарём, сохраняются в CSV и JSON | обработка сотен фото и расчёт метрик |
| пороги в разных местах кода | все в `config.py` | пороги можно варьировать и калибровать |
| главный объект — любой класс COCO | в режиме `car` — автомобиль (car/truck) и контекстные проверки | критерии главного фото |
| резкость по всему кадру с серой заливкой фона | резкость по области объекта в размере показа (1024 px) | заливка давала ложный перепад; оценка не зависит от размера файла |
| заполнение — сумма площадей рамок | площадь объединения рамок | пересекающиеся рамки не считаются дважды |
| пересвет: > 1 % пикселей ярче 240; недосвет: > 5 % темнее 15 | > 10 % пикселей ≥ 250 или ≤ 5 | белый кузов и чёрные шины не считаются дефектом |
| двойные штрафы за пересвет и за смаз | один штраф за дефект | один дефект — один штраф |
| технически годно = балл ≥ 7,5 | балл ≥ 7,5 и нет дефектов резкости и экспозиции | тёмное или размытое фото не проходит из-за малого штрафа |
| `cv2.imread` | `cv2.imdecode` | пути с кириллицей в Windows |

## Известные ограничения

- Пороги и штрафы подобраны эвристически, по визуальной оценке и искусственным искажениям; калибровка на размеченной выборке — во второй части работы.
- Пикселизацию индекс резкости не замечает.
- Отношение градиентов может принять за смаз сцену с сильными горизонтальными линиями.
- Водяные знаки и номерные рамки не обнаруживаются (нужно распознавание текста).
- Тип кадра не определяется.

Среднее время обработки фото из объявлений — 2,6 с на CPU (медиана 1,8 с).
